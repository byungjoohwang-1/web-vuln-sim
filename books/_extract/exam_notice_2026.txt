확인 등의 활동을 수행하는 자
※ 행정기관 및 공공기관 정보시스템 구축·운영 지침 (행정안전부고시 제2025-1호)
1) 자격기준: 
० 기본요건
 - 6년 이상 소프트웨어 개발분야 업무를 수행한 자
 - 3년 이상 소프트웨어 보안약점 또는 보안취약점 진단·분석업무를 수행한 자
० 교육요건
 - 기본요건을 만족하고 기본교육을 이수한 자
2) 자격 취득 기준: 
기본교육*을 수료하고 진단원 이수시험을 합격한 자
* 기본교육 : SW보안약점 진단원 기본과정(40시간, 5일)
3) 자격 유지기준: 
자격 취득 후 다음 해(1월~12월)까지 자격 유지되며,
이후 매년 보수교육* 수료를 통해 자격 유지
* 보수교육 : 연 1회(8시간) 진행
소프트웨어 개발보안 지식의 지속적인 습득 및 기술능력 유지를 위한 교육
※ 보수교육 미수료 시 다음 해(1~12월)부터 자격 정지

10
소프트웨어 보안약점 진단원 이수시험 안내서
 2026년 기본(양성)과정을 수료한 후, 자동응시 시험은 개별로 신청해야 하나요?
- 아닙니다.
기본(양성)과정 1,2차 수료자는 이수시험 1차, 3,4차 수료자는 이수시험 2차에 자동 응시 
처리되므로, 별도 신청은 필요 없습니다. 
※ 교육 종료 전 자동응시 시험에 대한 참석 여부 조사 시 '참석'으로 응답해 주시면 됩니다. 
- 단, 총 2회의 응시 기회 중 자동응시 1회는 실제 응시 여부와 관계없이 자동 차감됩니다.
※ 가급적 해당 일정에 맞춰 자동응시 시험에 응시하시는 것을 권장합니다.
- 선택응시 1회는 2027년까지 신청하실 수 있습니다.
 응시 횟수를 모두 소진한 경우, 어떻게 해야 하나요?
- 2025년 기본(양성)과정 수료자는 2026년 양성과정을 재수료한 후, 
   2026년 기본(양성)과정 수료자는 2027년 양성과정을 재수료한 후, 
   응시 자격을 다시 획득하실 수 있습니다.
- 단, 진단원 기본(양성)과정은 연 1회만 수강 가능합니다.

public static boolean checkPasswd(String password)  
{ 
  if (null == password || password.equals(“”))  {
    return false;
  }
  if (password.trim().length() < 6) { 
    LOG.info(“[ValidatorUtil_checkPasswd()] checkPasswd MIN8!!”); 
    return false;
  }
  for (int i = 0; i < password.length(); i++) { 
    char ch = password.charAt(i);
    if (! ((ch >= ‘0’ && ‘9’ >= ch) || (ch >= ‘a’ && ‘z’ >= ch)
      || (ch >= ‘A’ && ‘Z’ >= ch)
      || ch == ‘!’ || ch == ‘@’ || ch == ‘$’ || ch == ‘%’
      || ch == ‘^’ || ch == ‘&’ || ch == ‘*’)) { 
        LOG.info(“password not [“ + ch +“] !”); 
        return false;
      }
  }
  return true;
}

2.3.3. 비밀번호 저장
비밀번호는 개인정보보호법, 정보통신망법에서 일방향 해시로 암호화하여 저장하도록 규정하고 있다. 해시를 
사용할 경우에는 SHA2 이상의 알고리즘을 사용하여야 하며, 해시의 크래킹을 방어하기 위해 솔트를 반드시 적용

public String getPasswordHash(String password, byte[] salt) throws Exception  
{ 
  MessageDigest md = MessageDigest.getInstance(“SHA-256”); 
  md.update(password.getBytes());
  md.update(salt);
  byte byteData[] = md.digest();
  StringBuffer hexString = new StringBuffer(); 
  for (int i=0;i<byteData.length i++)  {
    String hex=Integer.toHexString(0xff & byteData[i]); 
    if (hex.length() == 1)  {
      hexString.append(‘0’);
    }
    hexString.append(hex);
  }
  return hexString.toString();
}
2.3.4. 비밀번호 재설정 및 변경
로그인한 사용자는 언제든지 비밀번호를 변경할 수 있도록 기능을 제공해야 하며, 장기간 비밀번호를 변경하
지 않고 사용자에 대해서는 3개월~6개월 단위로 비밀번호 변경을 유도해야 한다.
비밀번호 변경 시 이전 비밀번호 이력을 조회하여 이전 비밀번호를 연속해서 사용하는 것을 막아야 하며, 비밀번호 
변경 시에도 비밀번호 생성 규칙과 동일 규칙을 적용해야 한다.
사용자가 비밀번호를 분실한 경우, 비밀번호 찾기 기능으로 비밀번호를 재설정할 수 있도록 해야 한다.
비밀번호 찾기는 찾기 기능 버튼 클릭시 팝업 창에서 입력 받은 이메일 주소로 임시 비밀번호를 발송하며, 사용자는 
임시 비밀번호로 로그인할 수 있다.
임시 비밀번호로 로그인한 경우, 반드시 비밀번호를 변경 후 다시 로그인하도록 해야 한다.
2.3.5. 비밀번호 관리 규칙
비밀번호는 다음의 관리 규칙에 따라 관리되어야 한다.
- 비밀번호는 3개월~6개월 간격으로 변경해야 한다.
- 비밀번호 변경 이력을 관리하고, 이전 비밀번호를 연속해서 사용할 수 없도록 해야 한다.
- 최소사용기간 정책에 따라 비밀번호 변경 후 일정 기간 동안 비밀번호를 변경할 수 없도록 해야 한다.
- 마지막 로그인 시간을 관리하고, 일정 기간 동안 로그인하지 않는 사용자의 계정은 만료 처리해야 한다.
