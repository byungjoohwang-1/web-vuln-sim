# 개인 구독자를 위한 보안 교육 플랫폼 고도화·한국 개인정보 콘텐츠 확장안

작성·검색 기준일: 2026-09-13

대상: `C:\firebaseprojects\web-vuln-sim` / WEB-VULN-SIM

## 1. 제품 방향: 개인이 계속 공부하기 위해 구독하는 서비스

사용자가 지정한 고객은 **여러 보안 분야를 배우는 개인 구독자**다. 교육기관 판매·조직 관리·강사 콘솔은 이번 고도화의 중심에서 제외한다. 기존 기능은 유지하되 신규 투자는 개인의 학습 시작, 반복 실습, 복습, 실력 확인, 최신 내용 재학습에 집중한다.

권장 제품 약속은 **“내 수준에서 시작해, 보안 문제를 직접 해결하고, 바뀐 내용까지 계속 배우는 한국어 실습 플랫폼”**이다.

UI는 대대적인 개편이 필요하다. 첫 화면·탐색 구조·개인 학습 화면·실습 화면의 공통 틀을 바꾼다. 기존 515개 HTML을 한 번에 재작성하거나 프레임워크를 교체하는 작업은 우선순위가 아니다. 콘텐츠는 폭을 유지하면서 대표 과제의 깊이와 연결성을 높인다.

가장 먼저 만들 구독 이유는 다음 네 가지다.

1. **오늘 할 공부가 정해짐:** 관심 분야·수준·가용 시간에 맞춘 다음 과제.
2. **혼자 막히지 않음:** 현재 실습 증거를 읽는 단계별 AI 힌트.
3. **배운 것이 남음:** 오개념 복습과 다른 문제에서의 재검증.
4. **지난 지식이 낡지 않음:** 한국 개인정보 법령·안내서 변경을 개인의 학습 기록과 연결한 업데이트 학습.

가격·공급량·전환율은 아직 검증되지 않았다. 이 문서의 상품 구성과 운영 주기는 출시 실험안이며 매출 예측이 아니다.

## 2. 조사 범위와 최신 상태

### 2.1 수행한 조사

- 로컬 홈·허브·개인정보 도구·학습 기록·인증/동기화 소스와 기존 명세를 재확인했다.
- Chrome에서 로컬 최신 홈·보안 허브·개인정보 허브를 1440px/390px로 렌더링하고 화면을 확인했다. 서비스 워커는 차단했으며 기존 사용자 캐시 영향을 제외한 결과다.
- 공식 웹 자료를 검색했다. 한국 개인정보는 개인정보보호위원회·개인정보 포털·국가법령정보센터를 우선했다. 비교 서비스는 공식 제품 설명만 사용했다.
- 개인정보 도구 저장키가 공통 동기화 수집기에 들어가는지 합성 데이터로 메모리 테스트했다. 실제 개인정보·계정·운영 DB를 이용하지 않았다.

개별 안내서의 게시 정보와 열람 가능한 설명을 확인했으며 첨부 PDF 전체 조항과 모든 법적 판단 분기를 검수한 것은 아니다. 아래 신규 실습은 **교육 설계 제안**이다. 채점 조건을 확정할 때는 원문 해당 페이지·조문·시행일 대조가 필요하다.

## 3. 개인 구독 관점에서 현재 막히는 부분

### 3.1 모바일 핵심 허브가 여전히 잘림 — 즉시 수정

최신 로컬 재검사에서 390px 뷰포트의 `vuln-hub.html` 문서 폭은 **925px**였다. 제목·대표 버튼·카드의 오른쪽이 화면 밖으로 나간다. 이전 sidebar transform 수정은 존재하지만 그 수정만으로 전체 모바일 레이아웃이 해결된 것은 아니다.

홈과 개인정보 허브는 같은 검사에서 문서 폭 390px였다. 따라서 모든 화면이 동일하게 깨진다고 판단하지 않는다. 허브 내부 flex/grid의 최소 크기, CTA 행, 긴 문구, 조상 요소의 intrinsic width를 확인하고 실제 넘치는 요소를 줄인다. `overflow-x:hidden`으로 증상을 가리지 않는다.

- [홈 모바일 화면](assets/subscriber-review-2026-09-13/home-mobile.png)

**구독 영향 가설:** 모바일에서 무료 체험조차 완주하지 못하면 유료 전환과 재방문이 어려워진다. 전환 손실률 자체를 이번 조사에서 측정한 것은 아니다.

### 3.2 입구가 ‘공부 목표’ 대신 ‘도구와 자료 분류’를 요구함

초보 구독자는 ‘진단원 학습/훈련장/취약점 실습장’의 차이를 먼저 이해해야 한다. 홈 모바일에서는 첫 카드가 화면의 큰 부분을 차지해 개인정보 등 다른 선택지가 아래로 밀린다. 개인정보 허브는 유용한 도구가 있지만 첫 시작점이 기관의 영향평가 대상 판단이라 개인 입문자의 동기와 거리가 있을 수 있다.

**개선:** 가입 전에는 분야·학습 결과·무료 체험, 가입 후에는 이어서 공부·오늘의 복습·관심 분야 새 실습을 우선한다. 개인정보 입문 경로를 `개념과 판단`, `개발자 프라이버시`, `개인정보 실무`, `사례·심화`로 나눈다. PIA는 실무 경로의 선택 과제로 배치한다.

### 3.3 학습·복습·업데이트가 같은 기록으로 연결되지 않음

레드팀/문제 포지/실습장의 완료 이벤트는 추가됐지만 진도 카탈로그에는 해당 도구가 없다. 개인정보 `15_privacy-*`는 카탈로그에 있으나 `progress.js`의 자동 학습대상 정규식에서 빠져 있다. 개인정보가 `scenarios.json`에 독립 도메인으로 등록되지 않아 일부 AI 도구에서도 따로 떨어져 있다.

**개선:** 공통 콘텐츠 ID·활동 ID·버전을 기준으로 `최근 실습 → 결과 → 오개념 → 복습 → 다음 과제`를 연결한다. 도구 페이지 전체의 완료보다 개별 미션의 완료를 저장한다. 전체 도서관 대비 완료율 대신 **내가 선택한 경로의 완료율**을 보여준다.

### 3.4 신규 콘텐츠 수와 구독 가치가 혼동됨

취약/안전 버튼을 바꾸고 애니메이션을 보는 콘텐츠는 입문 설명에 도움이 된다. 유료 핵심 과제에는 학습자의 판단이나 수정이 결과를 바꿔야 한다. 법 조문 번호를 맞히는 문제도 실제 상황의 적용 조건을 구분하는 문제와 병행해야 한다.

**개선:** 콘텐츠를 `개념 체험`, `판단 문제`, `수정 실습`, `사건 해결`로 표시한다. 각 유료 대표 과제에는 학습 목표, 성공 조건, 실패 피드백, 변형 문제, 근거를 갖춘다. 단순 페이지 잠금만으로 구독 상품을 만들지 않는다.

### 3.5 신뢰 관련 결함은 개인 서비스에도 중요함

- `wvs_policy_builder`, `wvs_pia_assess`는 공통 `collectStore()`에 포함됨을 합성 데이터로 확인했다. 작성기 페이지 자체에 auth-widget가 없어도, 같은 출처에서 기록을 남긴 뒤 인증 위젯이 있는 페이지에 로그인하면 동기화 수집 대상이 된다. ‘브라우저 안에서만 처리/업로드하지 않음’ 안내와 맞는지 확인하고 저장 허용목록으로 전환한다.
- 운영용 `privacy-policy.html`에는 날짜 등의 초안 표시가 남아 있다. AI 사용 시의 공급자 전송, 익명 프록시 요청의 처리, 학습 데이터 동기화 범위를 실제 동작과 대조한다. 이번 문서는 그 자체로 법적 적합성 판정을 내리지 않는다.
- 서버 서명 수료증 외에도 브라우저 SHA-256 기반 스킬 자격 화면이 남아 있다. 자기 학습 기록·서버 검증 결과·공인 자격의 의미를 일관되게 구분한다.
- 현재 스킬 백분위는 교육용 기준 분포임을 이미 고지한다. 이를 실제 구독자 순위로 바꾸어 광고하지 않는다.

**완료 기준:** 사용자에게 표시한 저장/전송 범위와 네트워크 동작 일치, 개인 초안 자동 업로드 방지, 공용 기기 계정 전환 시 기록 혼합 방지, 결과별 평가 범위 표시. 수료증 재제출·동시성은 앞선 재평가 문서의 미해결 검증 항목을 함께 처리한다.

## 4. 무료 대안과 비교한 구독 가치

공식 [개인정보배움터][S01]는 무료 온라인 교육을 제공한다. [PortSwigger Web Security Academy][S02]도 무료 웹 보안 학습과 인터랙티브 실습을 제공한다. [TryHackMe][S03]는 무료/유료 개인 학습 경로를 운영한다. 따라서 자료 양이나 챗봇 유무만으로 유료 차별성이 성립한다고 보기 어렵다.

이 자료들을 바탕으로 한 **제품 가설**은 ‘한국어로 여러 분야의 보안 원리를 연결하고, 한국 개인정보 사례를 직접 판단·수정하고, 오개념과 법령 변경까지 개인별로 다시 학습하게 하는 서비스’다. 시장 독점성이나 경쟁사가 제공하지 않는다고 확인된 기능은 아니다.

| 개인 사용자 | 지금 해결하고 싶은 일 | 유료 가치 제안 |
|---|---|---|
| 입문·취업 준비 | 기초를 어디부터 쌓을지 알고 싶음 | 기초 진단·선수학습·짧은 실습·보이는 성장 |
| 개발자/현업 엔지니어 | 코드·API·데이터 설계에 보안을 적용 | 수정 실습·회귀 검증·AI 근거 피드백 |
| 개인정보 분야 학습자 | 조문 암기를 상황 판단으로 연결 | 한국 사례·적용 조건·기준일별 비교·문서 작성 연습 |
| 자동차/OT 심화 학습자 | 장비 없이 원리를 익히고 연관 문제를 풀기 | 제약이 명시된 시뮬레이션·프로토콜 로그·분야 간 전이 |

관심 분야는 여러 개 선택할 수 있게 한다. 개인정보 공부를 시작한 사람에게 첫날부터 자동차와 OT를 필수로 강요하지 않는다.

AI 채팅 횟수를 늘리는 것보다 F01~F06의 연결을 먼저 완성한다. 오답은 즉시 ‘역량 부족’으로 확정하지 말고 여러 증거를 모아 추천한다. 연속 학습을 놓쳤다고 누적 성취를 지우거나 불안감을 유도하지 않는다.

## 6. 대규모 UI 개편안

### 6.1 전역 구조

PC 상단: `로고 / 오늘의 학습 / 분야 탐색 / 사건 실습 / 내 기록` + 검색·계정.

모바일 하단: `오늘 / 탐색 / 복습 / 내 기록`. 현재 실습에서는 하단 메뉴보다 `저장·단계 이동`을 우선하고 기기 safe area와 키보드를 고려한다.

전역 메뉴에 모든 도구명을 나열하지 않는다. 레드팀·문제 포지 등은 분야/실습 메뉴와 전문가용 바로가기에서 접근한다. 언어 선택은 계정/공통 헤더 한 곳으로 통합한다. 현재 개인정보 허브처럼 공통 언어바와 페이지별 English 버튼이 동시에 보이는 구조를 정리한다.

### 6.2 가입 전 첫 화면

```text
WEB-VULN-SIM                         분야 탐색  이용 안내  로그인

나에게 필요한 보안을, 직접 해결하며 공부하세요.
IT · 자동차 · 산업 · AI · 한국 개인정보
[무료 실습 시작] [분야 둘러보기]

이런 문제를 풀게 됩니다:  요청 비교 / 개인정보 판단 / 수정 결과
선택한 분야의 입문 경로와 샘플 실습
무료 범위 · 구독에 포함되는 것 · AI 사용 범위 · 해지/기록 정책
```

대회 출품 문구는 소개/소식으로 이동한다. 홈의 최우선 메시지는 구독자의 공부 결과다. 회원가입 전에 샘플 실습의 목표→실행→결과를 한 번 경험할 수 있게 한다.

### 6.3 구독자 첫 화면

```text
오늘 15분, 개인정보 판단력을 한 단계 더
[이어서: 위탁과 제3자 제공 구분 / 2단계부터 / 계속]

오늘의 복습 3개                    이번 주 새 실습
틀린 개념 · 다음 복습              내가 관심 등록한 분야만

내 학습 경로                      내가 배운 내용의 변경
개인정보 기초 4/8                  적용 기준이 바뀐 항목 2개
웹 API 입문 2/6                   [변경점 확인 후 다시 풀기]
```

위 숫자는 와이어프레임 예시다. 실제 화면에는 실제 기록만 사용한다. 일정이 없는 사용자는 `오늘 5분/15분/30분`을 선택한다. 구독 만료 시에도 본인 노트·기존 결과 내보내기·계정 관리는 접근 가능하게 설계한다.

### 6.4 분야 탐색

큰 카드 수십 개 대신 경로 3~4개와 필터 가능한 목록을 제공한다. 각 항목은 `배울 것 / 난이도 / 예상 시간 / 실습 방식 / 검토 상태 / 무료·구독`을 보여준다. 항목 번호 PV-xx는 보조 메타데이터다.

개인정보 탭 예시: `처음 배우기 / 개발자 / 실무·사례 / 최신 변경`. ‘법률’, ‘시행령’, ‘안내서’, ‘권고’, ‘학습용 가정’을 같은 배지로 섞지 않는다.

### 6.5 개인용 실습

```text
사례 읽기 → 쟁점 찾기 → 판단/수정 → 검증 → 설명
목표: 동의 한 장으로 모든 처리를 허용할 수 있는지 구분

[사건과 증거]     [직접 입력·선택·코드]     [AI 힌트]
가상 자료        검증 버튼                정답 공개 단계 선택
적용 기준일      실패한 조건              근거 문서
```

모바일에서는 `실습 / 증거 / 코치` 탭, 폼과 표는 세로 재배치, 긴 코드는 해당 영역만 스크롤한다. 단순 판단 과제는 모바일 완주 가능하게 하고 긴 코딩 실습은 PC 권장을 표시하되 자료 읽기·노트·진도는 모바일에서도 이어진다.

### 6.6 읽기 편한 시각 체계

- 한국어 본문을 기본 16px/행간 1.6으로 통일하고 일반 UI의 세리프·코드 폰트 혼용을 줄인다.
- 다크 테마는 선택 가능하게 유지하되 개인정보의 긴 문서·표에는 라이트 읽기 모드를 제공한다.
- 본문·보조문구·구분선·선택·성공·오류를 CSS 토큰으로 관리한다. 색만으로 맞고 틀림을 전달하지 않는다.
- 이모지와 장식보다 제목·현재 단계·주요 버튼의 위계를 분명히 한다. 코드/요청/로그는 기존 전문 도구의 밀도를 보존한다.
- 주요 터치 제어는 44px를 사용성 목표로 삼는다. WCAG 최소 기준과 간격 예외는 별도로 확인한다. [W3C 대상 크기 기준][S04]

### 7.3 신규 모듈 상세 예시 3개

**K02 — 내 정보를 다른 서비스로 옮겨 주세요**

- 목표: 전송요구와 일반적인 자료 다운로드/제3자 제공을 구분한다.

- 판정: 과제에서 명시한 적용 조건의 올바른 분류, 범위 초과 차단, 상태·철회 이력 일치.
- 산출물: 전송 흐름도와 판단 근거. 실제 전송요구나 외부 서비스 연결은 수행하지 않는다.
- 변형: 같은 요청이라도 대상 기관/정보/기준일이 달라졌을 때 다시 판단한다.

**K04 — 앱 설정을 껐는데 왜 광고 이벤트가 나갈까요?**

- 목표: 화면 고지와 실제 SDK 데이터 흐름의 차이를 읽는다.
- 자료: 허구 앱의 이벤트 로그, SDK 수신자 목록, 설정 화면, 미완성 처리 설명.
- 조작: 필수 기능 이벤트와 분석/광고 이벤트를 나누고 식별자·수신자·조건을 수정한다.
- 판정: 지정된 선택 상태에서 해당 이벤트가 나가지 않고 필수 기능은 유지되는지 테스트.
- 산출물: 수정 전후 이벤트 표, 설명이 부족했던 지점, 남은 검토 질문.
- 법률 조건은 원문에 근거해 제시하고 EU 쿠키 규칙을 한국의 보편적 의무로 가져오지 않는다.

**K01 — 같은 사건, 날짜가 달라지면 무엇을 다시 확인할까요?**

- 목표: 사고 사실과 적용 법령 버전, 통지와 신고를 구분한다.
- 자료: 두 기준일의 가상 사건, 불확실한 조사 결과, 개인정보 종류/범위, 안내서 발췌.
- 조작: 확실한 사실/추정/미확인을 분류하고 대응·추가 확인·통지문을 작성한다.
- 판정: 원문으로 검토한 분기표와 누락 없는 설명. 모든 케이스에 동일한 타이머·신고 결론을 강제하지 않는다.
- 산출물: 적용 기준일이 적힌 대응 타임라인. 법령 변경 후 재학습 큐로 연결한다.

## 8. 한국 개인정보 콘텐츠 운영 방식

### 8.1 출처와 학습 버전을 연결

각 콘텐츠/문제에는 `sourceId`, 공식 URL, 문서명, 발간일, 게시일, 시행 시작/종료일, 확인일, 콘텐츠 버전, 검토 상태를 둔다. 날짜를 한 필드로 합치지 않는다.

```json
{
  "id": "privacy.breach.case01",
  "version": "2",
  "jurisdiction": "KR",
  "sourceIds": ["pipc-breach-2026-09"],
  "legalEffectiveFrom": null,
  "legalEffectiveTo": null,
  "reviewStatus": "needs_review",
  "reviewedAt": null,
  "assessmentMode": "scenario",
  "replacesVersion": "1"
}
```

위 값은 스키마 예시다. 법령 시행일과 검토일은 확인하지 않은 상태에서 자동 채우지 않는다. 같은 안내서에 여러 시점의 조항이 있으면 문제의 개별 판단 근거까지 나눈다.

### 8.2 업데이트가 복습으로 이어지게 만들기

1. 공식 자료 변경 후보 수집.
2. 기존 콘텐츠와 영향 범위 매핑.
3. 원문·현행법·정답 fixture 검토.
4. 기존 버전 보존 후 새 버전 발행.
5. 해당 주제를 공부한 사람에게 `바뀐 내용 3분 + 사례 1개` 제공.
6. 이전 수료를 삭제하지 않고 `업데이트 학습 필요` 상태를 추가.

개인정보위는 과거 안내서 정비를 추진한 바 있다. 검색에 나온 문서가 과거판인지 확인해야 한다. [안내서 정비 발표][S18] 최신성 배지를 달 때는 링크의 응답 여부와 내용 검토를 별개로 관리한다.

법령의 공개 정보·정오표·안전 관련 필수 정정 안내는 무료로 제공하고, 개인별 영향 정리·실습·복습·코칭이 구독 가치를 담당하게 한다.

### 8.3 지속 가능한 신규 공급안

검토할 운영 목표는 **월 1개 대표 사건 + 격주 1개 짧은 실습 + 기존 콘텐츠 교정·변형 문제**다. 확인되지 않은 법령 변경이나 생산량을 무조건 월간 약속으로 판매하지 않는다. 법령 변경이 없는 달에는 기존 사건의 다른 사실관계·다른 분야 적용을 제공한다.

매달 모든 보안 분야에 새 글을 채우기보다 주력 분야를 번갈아 깊게 다룬다. 이용자의 관심 분야에는 새 과제와 기존 약점 복습이 함께 나타나게 한다. AI가 대량 생성한 문제를 검토 없이 유료 출제하지 않는다.

## 9. 개인 구독 상품과 결제 경험

### 9.1 초기 구성

| 항목 | 무료 | 개인 구독 |
|---|---|---|
| 현재 공개 입문 자료 | 유지 | 동일 |
| 분야별 대표 체험 | 완주 가능한 샘플 | 전체 구독 경로와 심화 사건 |
| 학습 기록·기본 오답·정오표 | 제공 | 상세 약점·계획·버전별 재학습 |
| AI | 체험량 또는 정적 힌트 | 명확한 월 사용량을 포함한 맥락 코칭 |
| 신규 콘텐츠 | 예고·일부 샘플 | 검토 완료 심화 과제·변형 사건 |
| 개인 결과 | 기본 저장·내보내기 | 근거 연결 리포트·전이 평가 |

초기에는 유료 개인 플랜 1개를 권장한다. 분야별로 과도하게 쪼갠 구독은 여러 보안을 공부하려는 목표와 충돌한다. 무제한 AI는 비용을 측정하기 전에 약속하지 않는다.

가격은 결제 의향과 실제 사용 비용으로 검증한다. 예를 들어 월 19,900원/29,900원은 **잠재 고객 인터뷰용 가설**로 비교할 수 있으나 현재 적정가나 시장조사 결과가 아니다. 서로 다른 가격을 테스트할 때 혜택·표본·시점을 기록하고 단순 설문 응답을 구매로 집계하지 않는다. 연간 선결제는 월간 유지 가치가 확인된 이후 도입한다.

### 9.2 구매·해지 UI

- 결제 전에 총액, 청구 주기, 포함 기능, AI 한도, 갱신일, 해지 시점과 데이터 정책을 한 화면에서 확인하게 한다.
- 샘플 실습을 완주한 뒤 다음 경로를 소개한다. 답안을 입력한 중간에 갑자기 결제창으로 가리지 않는다.
- 내 계정에서 구독 상태·결제 내역·사용량·해지·기록 내보내기에 접근한다.
- 구독 종료와 계정 삭제는 별도 행동으로 분리한다. 다시 구독하면 이전 학습 위치를 복구한다.
- 결제 실패·중복 알림·환불·해지 후 재가입을 포함한 권한 상태를 서버에서 관리한다. 실제 계약·고지·청약철회 조건은 판매 방식에 맞는 적용 기준을 출시 전에 별도 확인한다.

### 9.3 구현상 주의

현재 공개 정적 파일을 CSS나 localStorage로 숨기는 것은 유료 접근 제어가 아니다. 새 유료 콘텐츠를 보호하기로 결정했다면 구독 권한 확인 후 서버에서 전달한다. 기존 공개 자료의 접근 정책 변경은 별도 결정으로 다룬다.

결제 결과는 서버가 검증하고 웹훅을 중복 처리하지 않도록 한다. AI 비용도 구독자별 사용량·전역 비용 상한과 연결한다. ‘구독 중’ 상태를 브라우저 값만 보고 허용하지 않는다. PG 선정과 결제 도입은 이 문서의 상품 검증 이후 구현 패키지다.
