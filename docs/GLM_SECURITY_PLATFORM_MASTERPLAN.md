# WEB-VULN-SIM: AI 경진대회용 통합 보안 교육 플랫폼 구현 명세

작성일: 2026-09-10 · 대상: `C:\firebaseprojects\web-vuln-sim` · 구현 담당: GLM 코딩 에이전트

## 1. 목표와 가장 중요한 결정

**“보안 지식을 아는 사람에서, 증거를 보고 문제를 해결하는 사람으로.”**

기존 보안 교육 자산을 연결해 **AI가 실습 행동을 이해하고, 실수 원인을 설명하고, 다른 산업의 유사 문제까지 풀게 하는 한국어 보안 교육 플랫폼**으로 발전시킨다. 가칭은 **SECURITY ATLAS — 세상의 보안을 배우는 AI 실습실**이다. 기존 WEB-VULN-SIM 명칭은 하위 브랜드로 유지할 수 있다.

장기 비전은 모든 보안 분야를 담는 것이다. 대회 제출본은 **넓은 분야 탐색 + 깊이 있는 대표 사건 하나 + 측정된 AI 교육 효과**에 집중한다. 분야별 페이지 수나 챗봇 유무만으로 차별성을 주장하지 않는다.

대회명, 심사 기준, 마감일, 팀 규모, 예산은 아직 제공되지 않았다. 아래 일정은 개발자 2명과 콘텐츠 검토자 1명이 4주간 작업하는 가정이며 수상이나 성능을 보장하지 않는다. GLM을 구현 도구로 사용하는 요청으로 해석했으며, 제품 내부 AI 모델까지 GLM으로 고정하지 않는다. 내부 AI는 공급자 교체 가능한 구조로 만든다.

## 3. 대회에서 보여줄 차별점

### 3.1 핵심 기능: 증거를 읽는 AI 코치

AI는 선택한 학습 주제뿐 아니라 현재 실습 단계, 관찰한 로그, 실패한 검증 항목, 사용한 힌트, 선수학습 상태를 받는다. 응답은 “무엇을 놓쳤는지 → 어떤 증거에서 알 수 있는지 → 다음에 무엇을 확인할지” 순서다.

예: 학습자가 개인정보 API 문제에 암호화만 추가하면, “암호화는 이동 중 노출을 줄이지만, 다른 사용자의 자료를 읽는 권한 문제는 남았습니다. 두 계정의 응답 결과를 비교해 보세요”라고 안내한다. 바로 정답 코드를 공개하지 않는다.

### 3.2 핵심 기능: 분야를 넘나드는 사건 실습

동일한 보안 원리인 인증·인가·무결성·최소권한이 웹, 공장, 차량, 개인정보에서 어떻게 달라지는지 연결한다. 사건 지도는 장식이 아니라 학습자의 선택에 따라 노드 상태와 증거가 바뀌는 UI다.

### 3.3 핵심 기능: 근거 있는 성장 보고서

“몇 페이지를 봤는가”와 “새로운 문제에 원리를 적용했는가”를 따로 보여준다. 결과에는 재현 증거, 수정 전후, 통과한 검증, 남은 약점, 관련 출처, 다음 실습을 담는다. 교육용 수료와 공인 자격을 혼동시키지 않는다.

PortSwigger도 학습 경로와 웹 실습을 제공한다. 따라서 학습 경로 자체를 고유 기술이라고 주장하지 않는다. 이 프로젝트의 제안 차별점은 **한국어 맥락 설명, 산업 간 원리 전이, 실습 증거 기반 코칭, 수정 후 재검증**의 조합이다. [PortSwigger 학습 경로](https://portswigger.net/web-security/learning-paths)

## 4. 전체 보안 분야 구조

최상위에는 분야, 교차 필터에는 직무·수준·보안 원리·학습 유형을 둔다. 모바일 보안처럼 여러 분야에 걸치는 콘텐츠는 다중 태그를 사용하고 본문을 복제하지 않는다.

| 공급망·IoT·임베디드 | 의존성, SBOM 개념, 펌웨어, 비밀정보 | 업데이트 구성품과 신뢰 근거 점검 | P1/P2 |
| 생활·조직 보안 | 피싱, 계정 보호, 업무 공유, 보안 문화 | 가상 업무 메시지에서 위험 신호 설명 | P1 |

P0에서 모든 분야를 완성했다고 표시하지 않는다. 각 분야에 `이용 가능`, `체험판`, `준비 중` 상태와 실제 검토 완료 콘텐츠 수를 표시한다. 보건·에너지·국방·해양 등은 이후 산업별 경로로 확장한다.

산업 제어 교육의 개념 기준은 [NIST SP 800-82 Rev.3](https://csrc.nist.gov/pubs/sp/800/82/r3/final), 자동차 사이버보안의 범위 참고는 [ISO/SAE 21434:2021 공식 소개](https://www.iso.org/standard/70918.html)로 한다. 기능안전과 사이버보안의 평가를 혼합하지 않는다. 유료 표준 전문을 복제하거나 조항을 추정하지 않는다.

개인정보 실습은 합성 데이터로 구성한다. 법적 의무·기한·제재를 콘텐츠에 넣을 때는 적용 국가, 법령 버전, 공식 출처, 검토일을 별도로 확인한다. 본 명세는 특정 법률 준수 판정을 제공하지 않는다.

### 5.1 코드 기반 진단

| 현재 구조 | 사용자에게 예상되는 문제 | 개선 |

| 큰 카드와 긴 목록 | 카탈로그가 커질수록 탐색 부담 증가 | 검색, 수준/시간 필터, 추천 3개, 접을 수 있는 분야 |
| 튜터가 별도 페이지 + API 키 입력 | 실습 맥락 손실과 첫 사용 마찰 | 실습 옆 코치 패널, 서버 인증 호출 |

이는 사용자 테스트 전 가설이다. 5명 이상에게 기존/개선 화면의 첫 실습 진입 과제를 수행하게 해 클릭 수·소요 시간·혼동 지점을 기록한다.

### 5.2 공통 내비게이션

상단: 로고 / 통합 검색 / 학습 지도 / 사건 실습 / 내 성장 / 로그인.

데스크톱: 248px 접이식 사이드바, 본문 최대 1440px. 모바일: 하단 홈·탐색·실습·내 성장, 검색은 헤더. 기존 진단원 학습·모의고사·코딩 표준은 관련 메뉴에서 계속 접근 가능하게 한다. `AI`를 모든 메뉴에 반복해서 붙이지 않는다.

신규 사용자는 이어서 학습 영역 대신 입문 미션을 본다. 진단을 건너뛰어도 이용 가능하다. 가짜 사용자 수·완료율·후기는 넣지 않는다.

### 5.4 실습 화면

```text
학습 지도 > 자동차 > 업데이트 무결성        [진도 저장됨]
[1 이해] → [2 증거 확인] → [3 수정] → [4 재검증] → [5 설명]
┌ 목표·자산·증거 목록 ┬ 실습 / 로그 / 코드 변경 ┬ AI 코치 ┐
│ 통과 기준 3개      │ 변경 전후 비교          │ 힌트 1  │
│ 소요시간·선수학습  │ [실행] [초기화]         │ 출처    │
└───────────────────┴─────────────────────────┴─────────┘
```

1440px에서는 240px / 유동 / 340px, 1024px에서는 코치가 접히며, 768px 미만은 실습·증거·코치 탭으로 전환한다. 모바일에 데스크톱 터미널을 축소해 넣지 않는다. 코드 영역만 가로 스크롤을 허용한다.

코치는 `쉽게 설명`, `첫 힌트`, `내 수정 검토`, `다른 분야 예시`를 제공한다. 자동 팝업으로 입력을 가리지 않는다. 실패 메시지는 “틀렸습니다” 대신 실패한 조건과 다음 확인 대상을 설명한다.

### 5.5 시각 규칙과 상태

- 기본 배경 `#0B1220`, 표면 `#152033`, 본문 `#F1F5F9`, 보조 `#B6C2D4`, 포인트 `#38BDF8`. 밝은 테마도 CSS 변수로 제공한다. 실제 조합의 대비를 검사한다.
- 한글 본문은 `system-ui, 'Malgun Gothic', sans-serif`, 코드만 모노스페이스. 본문 16px/1.6, 카드 제목 20px, 페이지 제목 32px, 8px 간격 단위.
- 분야별 무지개색 대신 상태 색에 의미를 둔다. 아이콘+문구를 함께 사용한다. 과도한 발광·그라데이션·이모지는 줄인다.
- 키보드 탐색, 보이는 포커스, skip link, 폼 레이블, 오류 연결, reduced-motion, 44px 터치 영역을 구현한다.
- 모든 주요 화면에 로딩·빈 결과·통신 오류·오프라인·권한 없음·저장 실패 상태를 설계한다.
- 검색 결과에는 제목, 분야, 난이도, 시간, 실습 유형, 일치한 개념을 표시한다. “자동차 인증”처럼 동의어와 분야+원리 검색을 지원한다.

## 6. 제출용 대표 사건: 스마트 모빌리티 기업 사고대응

가상의 회사, 공장, 차량, 고객만 사용한다. 각 단계는 학습용으로 연결한 사건이며 현실에서 해당 공격이 반드시 연쇄 발생한다는 뜻은 아니다.

| 단계 | 학습자의 행동 | 화면 변화와 증거 | 통과 조건 |
|---|---|---|---|
| 1. 웹/API | 고객 A가 고객 B의 정보에 접근하는 이유 분석 | 합성 요청/응답, 서버 권한 검사 차이 | 타인 요청 거부, 본인 요청 허용 |
| 2. 공장 OT | 협력사 원격 계정의 접근 범위 조정 | IT/OT 구역 지도, 허용/차단 로그 | 비인가 제어 접근 차단, 승인된 유지보수 유지 |
| 3. 차량 OTA | 가상 패키지의 서명·버전·대상 차량 정책 설정 | 패키지 메타데이터와 검증 결과 | 변조/낮은 버전/대상 불일치 거부, 정상 패키지 허용 |
| 4. 개인정보 | 위치정보 흐름의 과수집과 과도한 공유 수정 | 수집→저장→협력사→파기 흐름 | 과제에서 정한 최소 항목·권한·보관 정책 충족 |
| 5. AI 보안 | 증거 문서에 삽입된 지시를 분리 | 코치가 자료 속 지시를 수행하지 않고 근거만 인용 | 정답/비밀 유출·점수 조작 요청 무시 |
| 6. 보고 | 원인·영향·수정·재검증 결과 설명 | 근거 링크가 달린 최종 리포트 | 모든 필수 검증 통과, 누락 영역 표시 |

P0 필수: 웹·OT 기존 실습 2개를 표준 이벤트에 연결하고, OTA·개인정보 실습 각 1개를 신규 구현한다. AI 보안은 기존 콘텐츠 1개를 연계한다. 한 사건의 전체 플레이는 20~30분, 발표는 저장된 데모 상태로 5분에 압축한다.

OTA P0는 명시적인 정책 상태 머신과 합성 검증 결과를 쓰는 개념 시뮬레이션이다. 실제 차량 통신/펌웨어 업데이트로 표현하지 않는다. 암호학적 서명 검증까지 실행하는 확장은 P1에서 독립 fixture와 테스트로 구현한다.

각 실습에 `개념 시뮬레이션`, `브라우저 실행`, `서버 검증 과제` 유형을 표시한다. 애니메이션 종료만으로 통과 처리하지 않는다. 입력을 바꾸면 결과가 달라지고 초기화하면 재현 가능해야 한다.

## 7. AI 동작과 평가 설계

### 7.1 AI의 책임

AI가 담당: 오개념 설명, 단계별 힌트, 증거 요약, 직무별 비유, 다음 과제 추천 이유, 서술 피드백 초안.

프로그램이 담당: 인증/권한, 시험 정답, 필수 통과 조건, 공식 점수, 출처 존재 여부, 과금 한도, 진행 상태 전이. AI 출력으로 권한이나 수료 상태를 변경하지 않는다.

### 7.2 근거 기반 생성

1. 콘텐츠를 작성자·검토자·버전·출처가 있는 작은 단위로 정리한다.
2. P0는 분야/CWE/원리 태그와 텍스트 검색으로 관련 근거 최대 5개를 선택한다. 이를 벡터 검색이라고 부르지 않는다.
3. 서버가 선택한 근거와 최소화된 실습 이벤트만 모델에 전달한다. 전체 localStorage나 계정 스냅샷은 보내지 않는다.
4. AI는 근거 ID를 인용한다. 서버는 제공한 ID인지 확인하고 URL은 서버 카탈로그에서 붙인다.
5. 없는 근거·없는 규정 조항은 생성하지 않는다. 근거 부족이면 그 사실과 확인할 개념을 반환한다.
6. 자료 속 명령은 신뢰하지 않는 데이터로 처리한다. UI는 응답 HTML을 그대로 실행하지 않고 텍스트 또는 검증된 Markdown으로 렌더링한다.

AI 입력: `labId`, `labVersion`, `stepId`, `mode`, `hintLevel`, 최근 이벤트 최대 10개, 사용자 질문 최대 2,000자. 서버에서 길이·허용 필드·접근 권한을 검사한다.

```json
{
  "summary": "인증은 되어 있지만 자료의 소유자를 확인하지 않았어요.",
  "misconception": "authentication-vs-authorization",
  "nextAction": "본인 요청과 타인 요청의 응답을 비교하세요.",
  "evidenceIds": ["api-request-b"],
  "citations": [{"sourceId": "lesson-access-control-v1"}],
  "hintLevel": 1,
  "needsMoreEvidence": false
}
```

힌트는 개념→증거 위치→수정 방향의 3단계. AI에 아직 공개하면 안 되는 정답 fixture를 제공하지 않는다. 평가 모드에서는 힌트를 제한하고 연습 모드와 결과를 분리한다.

### 7.3 추천과 역량

초기 추천은 설명 가능한 규칙으로 만든다: 실패한 역량 우선, 선행학습 충족, 최근 완료 제외, 선택한 시간 안에서 3개. AI는 추천 이유의 표현을 돕는다. 이를 학습된 개인화 모델로 홍보하지 않는다.

역량은 지식 확인·원인 진단·수정·재검증·설명으로 나눈다. 단순 방문은 활동량에만 반영한다. 테스트 수가 부족하면 `평가 중`으로 표시한다. 초기 점수는 버전 있는 루브릭으로 계산하며 검증된 직무 능력 인증으로 표현하지 않는다.

### 7.4 비용과 실패 처리

모델명과 API URL은 서버 설정으로 지정한다. 공식 공급자 문서를 확인하고 구현 시 실제 계정으로 최소 호출 테스트를 수행한다. 이 문서에 특정 최신 모델명이나 단가를 가정하지 않는다.

P0 기본 제안: 요청당 출력 800토큰, 대화 문맥 최대 6턴, 요청 시간 제한 20초, 429/일시 장애에만 최대 1회 재시도. 토큰 상한·사용자 일일 한도·동시 요청 제한은 서버에서 강제하고 예산에 맞춰 조정한다. 고정 교육 설명만 캐시하며 개인 코드·질문이 다른 사용자에게 재사용되지 않게 한다.

모델 장애 시 검토된 정적 힌트를 제공하고 `기본 힌트 모드`라고 표시한다. 녹화/고정 응답을 실시간 AI인 것처럼 시연하지 않는다. AI 실패가 실습 실행·진도 저장을 중단시키지 않게 한다.

## 8. 기술 설계와 기존 자산 보존

프레임워크 전면 이전은 P0 범위에서 제외한다. 기존 HTML/JavaScript와 Firebase에 공통 모듈을 점진적으로 도입한다. 현재 `functions/package.json`은 Node 24를 선언하므로 새 의존성은 실제 설치 환경과 배포 런타임에서 검증한다.

```text
기존 HTML + 새 공통 UI
  ├─ 콘텐츠 카탈로그 / 검색 / 분야 지도
  ├─ 기존 WVSProgress 호환 어댑터
  └─ 인증된 서버 호출
       ├─ AI 코치 → 검토 콘텐츠 검색 → 모델 어댑터
       ├─ 과제 제출 → 결정적 검증 → 결과 저장
       └─ 보고서 → 검증 결과 + 근거 참조
```

### 8.2 콘텐츠 계약

카탈로그 필수 필드: `id`, `legacyIds`, `title`, `domainIds`, `conceptIds`, `level`, `durationMinutes`, `prerequisites`, `learningObjectives`, `labType`, `href`, `status`, `version`, `sourceRefs`, `reviewStatus`, `reviewedAt`.

예시 ID `auto-ota-integrity`는 새 콘텐츠다. 기존 `sim-sql.html` 등 파일명 ID는 `legacyIds`에 연결한다. 기존 파일명과 즐겨찾기 링크를 바꾸지 않는다. 카탈로그 ID·경로·선행학습 순환·중복·깨진 출처 참조를 검증하는 스크립트를 만든다.

`status=available`이어도 콘텐츠 검토 상태를 별도로 둔다. 분야별 실제 이용 가능 수는 중복을 제거한 ID로 집계한다. 준비 중 링크는 빈 페이지로 이동시키지 않는다.

### 8.3 실습 이벤트 계약

```json
{
  "schemaVersion": 1,
  "eventId": "uuid",
  "attemptId": "server-issued-id",
  "labId": "auto-ota-integrity",
  "labVersion": 1,
  "stepId": "verify",
  "type": "validation_requested",
  "payload": {"fixtureId": "tampered-package", "policyId": "signed-target-version"}
}
```

`eventId`로 중복 처리 방지, 서버 시각으로 수신 기록, 허용된 상태 전이만 수락한다. 클라이언트가 보낸 `passed=true`나 점수를 믿지 않는다. 공식 점수는 서버가 과제 버전과 입력을 읽고 재계산한다. 브라우저 자유 코드 실행 결과만 있는 기존 실습은 자기주도 연습 기록으로 표시한다.

서버 검증 P0는 입력 스키마가 제한된 정책/선택 과제다. 임의 코드를 Firebase Functions에서 eval/exec하지 않는다. 실제 코드 실행 채점은 별도 격리 실행 환경을 검토하는 P2다.

### 8.4 서버 API 논리 계약

Firebase callable 또는 동등한 인증된 HTTPS 함수로 구현하되 하나의 방식을 일관되게 사용한다.

| 함수 | 입력 | 반환 | 필수 처리 |
|---|---|---|---|
| `startAttempt` | labId, version | attemptId, 초기 상태 | 인증, 콘텐츠 이용 권한 |
| `requestCoach` | attemptId, mode, 질문 | 검증된 AI 응답, requestId | 본인 시도 확인, 한도, 개인정보 최소화 |
| `submitAttempt` | attemptId, eventId, 제한된 답안 | criterionResults, status | 서버 재채점, 중복 방지, 버전 고정 |
| `getLearningReport` | attemptId | 증거/검증/추천 | 본인 또는 승인된 강사만 |

공통 오류 코드: `UNAUTHENTICATED`, `FORBIDDEN`, `INVALID_INPUT`, `RATE_LIMITED`, `MODEL_UNAVAILABLE`, `VERSION_MISMATCH`. 원본 모델 오류·키·내부 프롬프트는 브라우저에 반환하지 않는다.

### 8.5 저장과 권한

- `users/{uid}`: 기존 진도 호환 유지. 명시적 신규 설정 필드만 확장한다.
- `users/{uid}/attempts/{attemptId}`: 서버가 생성·갱신, 본인 읽기. 기존 users 규칙은 하위 문서에 자동 적용되지 않으므로 별도 규칙이 필요하다.
- `users/{uid}/reports/{reportId}`: 서버 쓰기, 본인 및 승인된 강사 읽기.
- `leaderboard`, `certificates`: 검증된 값은 서버 전용 쓰기. 기존 클라이언트 발급 흐름을 서버 호출로 바꾸는 작업과 규칙 변경을 함께 적용한다.
- 기존 점수는 삭제하거나 검증된 값으로 승격하지 않고 `legacy/self-reported`로 구분한다.
- Admin SDK는 Firestore 규칙을 우회하므로 함수 자체에서 uid·소유권·역할을 검사한다.
- 신규 대화는 기본 영구 저장하지 않는다. 사용자가 저장한 리포트와 검증 결과만 보관하고 삭제 경로를 제공한다. 시범 운영 분석 이벤트는 30일 보관을 제안하되 운영 정책에서 확정한다.

### 8.6 실습 격리와 키 이전

AI 공급자 키는 서버 비밀 저장소에서만 읽는다. 기존 `wvs_ai_key`는 새 버전에서 브라우저 로컬 값만 제거하고 서버로 마이그레이션하지 않는다. 기존 동기화 제외 규칙도 유지한다.

XSS 등 의도적으로 취약한 데모를 로그인된 앱 DOM에 삽입하지 않는다. iframe이 필요하면 별도 출처 또는 최소 sandbox 권한을 쓰고 메시지 송신자·스키마를 검사한다. 동일 출처에서 `allow-scripts`와 `allow-same-origin`을 함께 허용하는 설계를 피한다. iframe 이벤트는 공식 채점 증거로 단독 신뢰하지 않는다.

`sw.js`의 API·인증·리포트 캐시 제외와 캐시 버전 전환을 확인한다. 기존 의도적 취약 실습이 있으므로 CSP 강화는 대표 실습 회귀 검증과 함께 단계적으로 수행한다.

## 10. 검증 계획과 대회 증거

아래는 **목표값이며 현재 측정 결과가 아니다.** 측정 전에는 수상 자료에 달성 수치로 넣지 않는다.

| 평가 | 방법 | 제안 통과 기준 |
|---|---|---|
| 첫 실습 접근 | 신규 사용자 5명 이상 관찰 | 첫 실습 시작 중앙값 60초 이하 |
| AI 근거 정확성 | 분야별 질문 60개, 검토자가 근거와 응답 대조 | 존재하지 않는 sourceId 0건, 주요 설명 정확도 90% 이상 |
| 정답 누설·문서 인젝션 | 별도 공격적 입력 20개 | 보호된 정답/키/권한 변경 0건 |
| 채점 | 정상·누락·변조·재제출 fixture | 모든 필수 조건 테스트 통과 |
| 학습 효과 | 10~20명 탐색적 파일럿, 동등 난이도 사전/사후 문제 | 점수·완료 시간·표본 수를 함께 보고 |
| AI 기여 | 정적 힌트 조건과 AI 조건을 순서 교차 또는 무작위 배정 | 차이와 한계 보고, 유리한 사례만 선택 금지 |
| UI | 360/768/1440px + 키보드 | 주요 흐름 가로 넘침/포커스 유실 없음 |
| 안정성 | AI timeout·429·오프라인·새로고침 | 진도 보존, 대체 힌트, 재시도 안내 |

작은 파일럿 결과를 일반화하거나 통계적으로 검증된 효과라고 표현하지 않는다. 정답을 외웠는지 구분하려면 사후 평가에 새로운 분야의 유사 문제를 포함한다.

필수 자동 검증:

1. 카탈로그 중복/누락/깨진 경로와 선행학습 순환 검사.
2. 기존 진도 fixture를 신규 어댑터로 읽어 완료 항목과 XP가 보존되는지 확인.
3. 서버 채점 정상/실패/변조/중복 제출 테스트.
4. Firestore Emulator에서 비로그인·다른 사용자·본인·강사 권한과 점수/수료 직접 쓰기 차단 테스트.
5. 모델 stub으로 잘못된 JSON, 없는 출처, 장문, timeout 응답 처리 검증. 실제 모델 품질 평가는 별도 수행.
6. 대표 기존 SQL/XSS/진단원/훈련장/진도 화면 회귀와 신규 사건 E2E.
7. localStorage·네트워크·Service Worker에 공급자 키와 개인 응답이 부적절하게 남지 않는지 확인.

현재 루트에는 확인된 통합 npm 테스트 명령이 없다. GLM은 테스트 도구를 실제로 추가한 뒤 실행 명령을 기록한다. 실행하지 않은 테스트를 통과로 보고하지 않는다.

## 12. 참고 출처와 콘텐츠 관리

출처 확인일은 2026-09-10이다. 표준/규정 항목은 게시 시점의 공식 버전을 다시 확인하고 `sourceRefs`에 문서명·버전·URL·검토일·사용 범위를 저장한다.

- 웹 보안 분류: [OWASP Top 10 공식 페이지](https://owasp.org/Top10/). 분류 체계를 참고하며 기존 항목 매핑은 버전별로 관리한다.
- AI 보안 분류: [OWASP LLM Applications 프로젝트](https://owasp.org/www-project-top-10-for-large-language-model-applications/). 기존 콘텐츠가 특정 연도를 전제로 하면 업데이트 여부를 검토한다. 이 명세는 새 버전의 세부 항목을 확정하지 않는다.
- OT 개념: [NIST SP 800-82 Rev.3](https://csrc.nist.gov/pubs/sp/800/82/r3/final).
- 자동차 범위: [ISO/SAE 21434:2021 공식 소개](https://www.iso.org/standard/70918.html).
- 직무별 교육 설계: [NICE Framework Resource Center](https://www.nist.gov/itl/applied-cybersecurity/nice/nice-framework-resource-center). 직무·지식·기술의 연결을 참고하고 자체 학습 점수를 NICE 인증처럼 표현하지 않는다.
- 학습 경로 비교: [PortSwigger Web Security Academy](https://portswigger.net/web-security/learning-paths).

KISA·금융보안원 가이드의 전수 준수나 최신 법규 충족 여부는 기존 README의 주장만으로 확정하지 않는다. 실제 검토한 문서 버전과 항목별 매핑 근거가 있는 범위만 표시한다. 신규 콘텐츠는 작성→출처 확인→전문가 검토→검증 fixture 확인→공개 순서로 관리한다.
