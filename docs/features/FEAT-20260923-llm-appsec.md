# FEAT-20260923-llm-appsec — LLM 앱·게이트웨이 보안 실습

## 배경 (PO) — 최신 취약점 구동
KEV(실제 악용 중) 피드 상위 3건이 전부 **BerriAI LiteLLM**(LLM 게이트웨이/프록시):
- CVE-2026-59822 Improper Authentication (인증 우회)
- CVE-2026-42271 Command Injection (명령 주입)
- CVE-2026-42208 SQL Injection

LLM 게이트웨이/애플리케이션(프록시·오케스트레이터·RAG 백엔드)은 급속히 표준 인프라가
됐지만, 이 포털의 sim-agentic-ai 는 **에이전트/도구 계층**(프롬프트 인젝션·과도한
에이전시)을 다루지 그 아래 **앱·인프라 계층**(게이트웨이 인증·주입·SSRF·키 격리·비용)은
공백이다. 실제 악용 중인 CVE 군이 정확히 이 계층이다.

## 목표
모의 LLM 게이트웨이 **OrbitLLM Gateway**(전부 인페이지 mock)에 요청을 던져 앱/인프라
계층 약점을 시험하고, OWASP LLM Top 10(앱측)·일반 웹 보안으로 방어한다.

## 도전 (9)
- L1 게이트웨이 인증 우회 (CVE-2026-59822) — 마스터/가상키 검증 부재
- L2 명령 주입 (CVE-2026-42271) — 콜백·파일경로·설정에서 OS 명령 실행
- L3 SQL 주입 (CVE-2026-42208) — 사용량/로그 DB 파라미터 미검증
- L4 SSRF — 앱이 임의 URL fetch(모델 endpoint·문서 로더) → 내부/메타데이터
- L5 프롬프트 템플릿 주입 — 사용자 입력이 시스템 프롬프트에 직접 연결
- L6 안전하지 않은 출력 처리 — LLM 출력을 그대로 렌더/실행 → XSS/코드실행
- L7 API 키·비밀 유출 — 다중 테넌트 키 격리 부재, 로그/응답에 키 노출
- L8 무제한 소비 (비용/DoS) — rate limit·예산 부재
- L9 모델·엔드포인트 접근제어 부재 — 권한 없는 모델/관리 라우트 호출

## 방식
DEF 플래그 단일 진실원천 엔진(공격→취약/양호 판정→방어→재점검). 도전마다 고유 공격
동사로 매칭(분기 충돌 예방). "쉽게 말하면" 비유 + 방어 짝. 데모 키·토큰은 EXAMPLE 값.

## 완료 기준 (QA)
- 브라우저 전수 순회 9도전: 공격 인식·출력 충돌 없음·방어 후 출력 변화·양방향 채점.
- predeploy 게이트 전체 통과(레지스트리 대비값·a11y·deadlink·문법).
- 홈 라이브 카드 + 허브 #menuAI 배선.
