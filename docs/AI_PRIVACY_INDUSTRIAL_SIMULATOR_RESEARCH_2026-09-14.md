# 개인정보·산업보안·AI 보안 시뮬레이터 추가 조사

조사일: 2026-09-14  
목적: 원티드 AI Championship 출품을 위한 추가 후보 선정. [대회 재분석](WANTED_AI_CHAMPIONSHIP_REASSESSMENT_2026-09-14.md)의 보충 문서다.

## 1. 결론

추천 1순위는 **“AI 업무 비서의 고객정보·기술자료 유출을 막는 실습”**이다. 같은 엔진에서 금융 고객상담, 자동차 정비, 제조 협력사 문서 검색이라는 세 가지 맥락을 제공하면 개인정보·산업보안·AI 보안을 자연스럽게 연결할 수 있다.

현재 사이트의 AI-02 간접 인젝션, AI-07 도구 권한, AI-09 RAG, AI-19 기밀 유출과 겹치는 개념이다. 추가 가치는 **설명 카드 → 사용자가 검색 권한·도구 범위·전송 정책을 수정하고 실제 결과를 비교하는 완결된 과제**로 발전시키는 데 있다.

아래 ‘기존 도구’는 공식 문서·개발자 저장소에서 확인했다. ‘추가할 실습’은 이를 참고한 자체 제안이며 이미 존재하는 상용 제품처럼 서술하지 않는다. 외부 도구의 설치·실행·호환성 검증은 이번 조사에서 수행하지 않았다.

## 4. 우선 추천하는 추가 실습 8개

### SIM-01. AI 고객상담 비서 — 타인의 개인정보 유출 방어

- 분야: 개인정보 + 금융 + RAG 보안.
- 상황: 고객 A의 상담을 처리하는 AI가 검색 결과에 섞인 고객 B의 정보를 답변에 포함할 수 있다.
- 학습 조작: 사용자·고객 소유 관계, 검색 전 권한 필터, 캐시 범위, 결과 최소화 정책.
- AI 역할: 상담 요약·답변 생성, 실패한 증거에 대한 힌트.
- 판정: 합성 고객 B의 식별용 표식이 답변·도구 실행 결과에 나타나는지 검사. 고객 A의 정당한 문의가 해결되는지도 함께 확인.
- 성공 조건: 비인가 데이터는 검색 단계부터 배제되고 정상 상담은 유지. 출력 마스킹만으로 원인 해결이라고 인정하지 않음.
- 기존 연결: `13_ai-ai09.html`, `privacy-hub.html`, 금융 인가 과제.
- 근거: [Promptfoo RAG/에이전트 평가][T05], [개인정보위 AI 안내][R06].
- 우선순위: **제출 전 1순위**, 단 기존 대표 사고 시연을 깨지 않는 독립 확장으로 제한.

### SIM-02. 협력사 문서를 읽는 AI — 제조 기술자료 유출 방어

- 분야: 산업기술 보호 + AI 에이전트 + 공급망.
- 상황: 협력사 정비 문서에 작업 지시처럼 보이는 내용이 섞여 AI가 다른 프로젝트의 기술자료까지 읽으려 한다.
- 학습 조작: 문서의 신뢰 수준, 프로젝트별 읽기 권한, 내보내기 도구 범위, 실행 전 정책 검증.
- AI 역할: 문서에서 정비 요약을 만들고 제한된 도구 호출을 제안.
- 판정: 허용 프로젝트 문서만 읽었는지, 합성 기밀 표식이 모의 외부 전송함으로 넘어갔는지, 정상 정비 요약이 완성됐는지.
- 성공 조건: 정상 요약은 가능하고 권한 없는 읽기·내보내기는 실행 경계에서 차단.
- 기존 연결: `industry-tech-protect.html`, `13_ai-ai02.html`, `13_ai-ai07.html`, `13_ai-ai19.html`.
- 근거: [AgentDojo][T02], [OWASP ACS][R03], [기술보호울타리][R08]. 산업 시나리오는 자체 교육 설계다.
- 우선순위: **SIM-01과 같은 엔진을 재사용할 때 2순위**.

### SIM-03. MCP 도구 권한 실험실

- 분야: 최신 AI 보안 + 개발보안.
- 상황: 읽기용으로 추가한 도구의 설명·기능이 바뀌거나, 비슷한 이름의 도구가 과도한 권한을 요청한다.
- 학습 조작: 허용 도구, 인자 범위, 대상 자원, 버전 변경 재검토, 실행 정책.
- AI 역할: 도구를 고르는 비서. 도구 실행 허용 여부는 별도 규칙이 판정.
- 판정: 선택한 도구와 실제 인자·자원·호출 결과를 추적. 정당한 읽기는 유지하고 권한 밖 동작은 차단.
- 기존 연결: 과도한 에이전시 카드와 가드레일 실습. 현재 확인한 5개 가드레일 미션의 단순 재복제가 아님.
- 근거: [DVMCP][T01], [Promptfoo MCP 평가][T09], [ACS][R03].
- 우선순위: 개념 시연은 작게 가능하지만 완전한 MCP 런타임 통합은 후속 작업. 모의 도구라면 ‘MCP 흐름 모형’이라고 표시.

### SIM-04. 권한 회수 후에도 기억하는 AI

- 분야: 개인정보 + 산업보안 + 에이전트 기억·캐시.
- 상황: 프로젝트 접근 권한을 회수했는데 과거 대화·요약·캐시에서 제한 정보가 계속 나온다.
- 학습 조작: 사용자별 기억 분리, 캐시 키의 권한 범위, 만료·무효화, 조회 시 재인가.
- AI 역할: 이전 대화와 문서를 참고하는 업무 비서.
- 판정: 신규 검색·기억 조회·답변의 각 단계에서 권한 회수된 정보가 재등장하는지 비교.
- 성공 조건: 권한 회수 뒤 해당 정보의 재접근은 차단하되 공개 지식과 정상 작업은 유지.
- 기존 연결: AI-09·AI-24·개인정보 권리 행사 콘텐츠.
- 근거: [Promptfoo 에이전트 테스트 문서][T10], [Agentic Top 10][R02]. 구체적 과제는 자체 제안.
- 우선순위: 후속 대표 과제. ‘삭제 버튼을 누르면 모델이 학습한 정보를 완전히 잊는다’고 설명하지 않음.

### SIM-05. 가명·합성 데이터 — 정말 재식별 위험이 줄었나

- 분야: 개인정보 보호 + 데이터/AI.
- 상황: 이름을 지운 합성 의료·급여·구매 자료를 다른 합성 표와 연결하면 개인을 좁혀갈 수 있다.
- 학습 조작: 속성 제거, 범주 일반화, 희귀 조합 처리, 합성 방식 비교.
- AI 역할: 변환안·학습 설명을 제안. 위험 수치는 통계 평가기로 계산.
- 판정: 개별 식별·연결·추론 위험과 분석 유용성을 함께 표시하고 표본·불확실성을 공개.
- 기존 연결: `pseudonym-lab.html`, `privacy-pseudonym-process.html`, 멤버십 추론 카드.
- 근거: [Anonymeter][T07].
- 우선순위: 개인정보 트랙 차별화에 좋음. 실제 인물 정보 대신 합성 원본·합성 보조 데이터를 사용. 낮은 점수를 법적 익명성 보증으로 표시하지 않음.

### SIM-06. 차등 프라이버시 예산 실험실

- 분야: 개인정보 + AI 데이터 활용.
- 상황: 반복적인 집계 질의에서 정확도와 프라이버시 보호 수준을 비교한다.
- 학습 조작: 명확히 정의한 집계·민감도·노이즈·질의 횟수·프라이버시 예산.
- AI 역할: 학습자 수준에 맞춘 해설. 수학적 계산과 예산 집계는 고정 구현.
- 판정: 반복 실행 오차 분포와 예산 소모. 동일 데이터에서 공격 성공률 하나만으로 DP 보장을 주장하지 않음.
- 기존 연결: 가명정보 도구에 심화 실습으로 연결.
- 근거: [NIST SP 800-226 및 보충 노트북][R07].
- 우선순위: 제출 후. 통계·수학 검토가 필요하며 AI 필수성이 상대적으로 낮음.

### SIM-07. 스마트공장 AI 정비 비서 — 읽기와 제어 권한 분리

- 분야: OT·산업보안 + AI 에이전트.
- 상황: AI에게 상태 진단만 맡겼는데 제어 설정 변경까지 제안하거나 실행하려 한다.
- 학습 조작: 읽기/쓰기 도구 분리, 정비 시간·설비 범위, 승인 단계, 망 경로.
- AI 역할: 합성 설비 로그 요약·진단 가설 제시. 설비 제어는 모의 API로 한정.
- 판정: 정상 조회 가능, 허용 범위 밖 변경 차단, 허가된 정비 후 서비스 상태 보존.
- 기존 연결: `12_ics-*` 원격 유지보수·제어 로직·망 분리 콘텐츠.
- 근거: [KISA OT 안내][R05], [NIST SP 1800-45][R04], [ACS][R03].
- 우선순위: SIM-02의 확장. 공정 물리 모델이 없으면 실제 공장 디지털 트윈이라고 부르지 않음.

### SIM-08. AI가 제안한 보안 패치 — 취약점만 막고 서비스도 살렸나

- 분야: 웹·시스템·금융 + AI 활용 취약점 분석.
- 상황: AI가 만든 수정안이 악성 요청을 막지만 정상 로그인·조회·거래도 실패시킨다.
- 학습 조작: 수정안 비교, 테스트 선택, 검증 결과를 읽고 보완.
- AI 역할: 제한된 과제의 패치 후보·설명 생성.
- 판정: 취약 사례 재현, 정상 회귀 테스트, 허용된 실행 환경에서 결과 확인.
- 기존 연결: AI 생성 코드 10개, 코드 수정 실습, 대표 사건의 과차단 검사.
- 근거: 기존 로컬 구현의 확장 제안. 외부 AI가 임의의 취약점을 완전히 탐지·수정한다고 주장하지 않음.
- 우선순위: **새 제품을 만들기보다 기존 대표 시연 강화에 가장 빠르게 적용 가능**.

## 5. 대회용 최소 구현안

SIM-01의 고객상담 문서 6개, 사용자 역할 3개, 합성 요청 8개로 작은 실습을 만든다는 설계안이다. 숫자는 제작 목표이며 현재 구현량이 아니다.

1. ‘내 고객 상담 요약’이라는 정상 업무를 제시한다.
2. 취약 설정에서 다른 고객 문서가 검색되는 것을 보여준다.
3. 사용자가 검색 권한·전송 범위를 바꾼다.
4. 동일 입력으로 다시 실행하여 정상 상담과 정보 차단을 함께 확인한다.
5. 실패한 검색·도구 호출·답변을 AI 코치가 설명한다.
6. 같은 엔진에 제조 협력사 문서 세트를 넣어 산업보안 전이 과제를 연다.

추천 화면은 `업무 요청 → 검색된 문서 → AI 제안 → 도구 정책 판정 → 최종 결과`의 타임라인이다. 내부 추론을 보여준다고 표현하지 않고 관찰 가능한 입력·출력·도구 이벤트만 보여준다.

판정은 ‘유출 차단율’과 ‘정상 업무 성공률’을 따로 낸다. 전부 거부해서 유출을 막은 설정은 합격하지 않는다. 같은 조건을 반복 측정하며 모델·프롬프트·fixture·평가기 버전을 보존한다. 저장된 예시와 실제 모델 실행을 구분한다.

AI는 공격 사례의 표현 변형·업무 수행·코칭에 활용할 수 있다. 초기에는 사람이 검토한 변형 목록으로 시작하고, 생성한 사례는 정상 업무와 성공 조건을 확인한 뒤 추가한다. 합성 기밀과 모의 전송함만 사용하는 고정된 학습 환경으로 구성한다.

## 6. 선택 제안

- **제출까지:** 기존 대표 사건 완성 + SIM-01 한 개. SIM-08의 정상 회귀 검증 관점을 재사용.
- **같은 엔진으로 확장:** SIM-02 제조 협력사 → SIM-03 MCP 정책 → SIM-07 OT 정비.
- **개인정보 심화:** SIM-05 재식별 위험 → SIM-06 차등 프라이버시.
- **운영 평가:** Promptfoo 또는 PyRIT 중 필요에 맞는 하나부터 검토. 모든 외부 도구를 한 번에 설치하지 않음.

공개 도구의 존재 자체는 독창성의 근거가 아니다. **한국어 산업 사례, KISA·개인정보위 자료 연결, 사용자가 고친 방어의 검증, 다른 분야로 이어지는 학습**을 직접 구현·측정하는 것이 이번 프로젝트의 기여다.
