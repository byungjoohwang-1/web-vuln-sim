# 오류상황 대응 부재 / 빈 catch · CWE-391 · KISA 에러처리

## 개념
CWE-391은 예외나 오류 조건이 발생했는데도 이에 대한 어떤 대응도 하지 않는 약점이다. 대표적으로 예외를 잡기만 하고 아무것도 하지 않는 "빈 catch 블록"이 있다. 오류가 조용히 삼켜지면 프로그램은 실패를 인지하지 못한 채 잘못된 상태로 계속 진행한다.

## 취약 원인
- `catch (IOException e) { }`처럼 예외를 잡은 뒤 로깅·복구·재던지기 없이 무시했다.
- 오류가 발생했다는 사실이 로그에도 남지 않아 운영 중 원인 추적이 불가능하다.
- 실패한 작업(설정 로딩 등)의 결과를 검증하지 않고 후속 로직이 진행된다.

## 공격 시나리오(영향)
- 설정/인증/검증 단계의 실패가 무시되어 보안 기능이 우회되거나 기본값으로 동작한다.
- 자원 정리 실패가 감춰져 자원 누수와 장애가 누적된다.
- 장애 발생 시 어디서 무엇이 잘못됐는지 알 수 없어 대응이 지연된다.

## 안전한 코딩
- 잡은 예외는 반드시 처리한다: 최소한 `logger`로 원인을 기록한다.
- 호출자가 실패를 알아야 하면 의미 있는 예외로 다시 던진다(`throw`).
- 복구 가능한 경우 명확한 대체 경로(기본값·재시도)를 둔다.
- 자원은 try-with-resources로 확실히 해제한다.

## 취약 vs 안전 차이
| 구분 | 취약 (Vulnerable.java) | 안전 (Secure.java) |
|------|------------------------|---------------------|
| catch 내용 | 빈 블록(무시) | 로깅 + 재던지기 |
| 실패 인지 | 불가능 | 로그·예외로 전파 |
| 자원 해제 | 누락 | try-with-resources |
| 후속 로직 | 잘못된 상태로 진행 | 호출자가 대응 |
