# 제거되지 않고 남은 디버그 코드 (CWE-489 / KISA 6.02 캡슐화)

## 제목
- 약점명: 제거되지 않고 남은 디버그 코드
- CWE: CWE-489 (Active Debug Code)
- KISA 개발보안 가이드(2021) 항목: 6.02 (캡슐화)

## 개념
개발/디버깅 편의를 위해 넣은 콘솔 출력, 디버그 플래그, 인증 우회(백도어)
로직이 운영 배포본에 그대로 남는 문제다. 공격자는 이런 코드를 통해 내부
정보를 얻거나 인증을 우회할 수 있다.

## 취약 원인
- `boolean DEBUG = true` 같은 플래그로 디버그 모드가 켜진 채 배포된다.
- `System.out.println(...)`, `printStackTrace()` 로 사용자/비밀번호/스택트레이스가 노출된다.
- 마스터 비밀번호 같은 개발자 백도어로 정규 인증을 우회한다.

## 영향
- 내부 상태, 자격증명, 스택트레이스 등 민감정보 노출.
- 백도어를 통한 인증 우회 및 권한 상승.
- 로그·콘솔을 통한 정보 수집으로 후속 공격이 쉬워진다.

## 안전한 코딩
- 배포 전 모든 디버그 출력·플래그·우회 로직을 제거한다.
- 진단이 필요하면 표준 로깅 프레임워크로 레벨을 나누고 민감정보는 남기지 않는다.
- 인증은 오직 정규 경로(사용자 조회 + 검증)만 허용하고 우회 경로를 두지 않는다.

## 취약 vs 안전 차이
- 취약: 디버그 플래그 + 콘솔 출력 + `printStackTrace()` + 마스터 비밀번호 백도어.
- 안전: 디버그 흔적 없음, `java.util.logging` 으로만 결과 기록, 우회 경로 제거.

## CWE·KISA 매핑
- CWE-489: Active Debug Code
- KISA 개발보안 가이드(2021) 6.02 캡슐화 — 제거되지 않고 남은 디버그 코드

## 실행/컴파일 방법
```bash
javac Vulnerable.java Secure.java
java Vulnerable   # 백도어 로그인 성공 재현
java Secure       # 정규 경로만 통과
```
