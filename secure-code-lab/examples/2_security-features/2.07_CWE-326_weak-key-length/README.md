# 충분하지 않은 키 길이 사용 (Inadequate Encryption Strength) — CWE-326 / KISA 2.7

## 개념
암호 알고리즘 자체는 표준이라도 키 길이가 너무 짧으면 전수조사·인수분해로
키를 복원할 수 있어 실질적인 안전성이 무너지는 약점이다.

## 취약 원인
- RSA 1024비트, DES 56비트처럼 권고 미달의 짧은 키 길이를 사용한다.
- 과거 예제/레거시 설정을 그대로 복사한다.
- "동작하기만 하면 된다"는 판단으로 키 길이를 검토하지 않는다.

## 공격 시나리오
1. 공격자가 1024비트 RSA 공개키로 서명·암호화된 데이터를 수집한다.
2. 충분한 연산 자원(클라우드/전용 하드웨어)으로 모듈러스를 인수분해한다.
3. 복원한 개인키로 서명 위조·복호화를 수행한다.

## 안전한 코딩
- RSA는 최소 2048비트, 장기 보관용은 3072/4096비트를 사용한다.
- 대칭키(AES)는 256비트, ECC는 256비트 이상 곡선을 사용한다.
- 알고리즘·키 길이 정책을 문서화하고 주기적으로 재검토한다.

## 취약 vs 안전 차이
| 구분 | 취약(Vulnerable) | 안전(Secure) |
|------|------------------|--------------|
| RSA 키 길이 | 1024비트 | 2048비트 이상 |
| 인수분해 난이도 | 현실적 위협 | 현재 안전 |
| 장기 보관 | 부적합 | 3072/4096 권장 |

## CWE·KISA 매핑

- KISA 소프트웨어 개발보안 가이드(2021.12) 2.7 충분하지 않은 키 길이 사용

