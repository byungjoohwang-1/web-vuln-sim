# 취약한 비밀번호 허용 (Weak Password Requirements) — CWE-521 / KISA 2.09

## 개념
사용자 인증에 쓰이는 비밀번호에 대해 충분한 복잡도(길이·문자 종류 조합)를 요구하지 않으면,
공격자는 사전 대입(dictionary attack)이나 무차별 대입(brute force)으로 쉽게 비밀번호를 알아낸다.
"취약한 비밀번호 허용"은 애플리케이션이 약한 비밀번호를 그대로 받아들이는 설계·구현상의 약점이다.

## 취약 원인
- 최소 길이 검사가 없거나 지나치게 짧다(예: 4자 초과이면 통과).
- 대문자/소문자/숫자/특수문자 조합을 강제하지 않는다.
- `password`, `12345678` 같이 널리 유출된 흔한 비밀번호를 차단하지 않는다.
- 결과적으로 엔트로피가 낮은 비밀번호가 계정 보호선이 되어 버린다.

## 공격 시나리오
1. 공격자가 대상 계정 ID를 확보한다.
2. 흔한 비밀번호 목록/사전 파일로 자동 로그인 시도를 반복한다.
3. 정책이 약해 짧고 단순한 비밀번호가 허용되므로 짧은 시간 안에 적중한다.
4. 계정 탈취 후 권한 상승·정보 유출로 이어진다.

## 안전한 코딩
- 최소 길이를 8자 이상(민감 서비스는 그 이상)으로 요구한다.
- 대문자·소문자·숫자·특수문자를 각각 최소 1개 이상 포함하도록 정규식으로 강제한다.
- 유출된 흔한 비밀번호 목록과 대조해 차단한다.
- 정책을 상수/설정으로 명시해 리뷰와 변경 이력을 남긴다.
- (추가) 반복 시도 제한(2.16), 솔트 해시 저장(2.14)과 함께 적용한다.

## 취약 vs 안전 차이
| 구분 | 취약(Vulnerable) | 안전(Secure) |
|------|------------------|--------------|
| 길이 | `length() > 4` 만 확인 | `length() >= 8` 요구 |
| 복잡도 | 없음 | `matches(정규식)` 로 4종 문자 강제 |
| 흔한 비밀번호 | 허용 | 차단 목록으로 거부 |
| 정책 명시 | 없음 | `PASSWORD_POLICY` 상수 |
