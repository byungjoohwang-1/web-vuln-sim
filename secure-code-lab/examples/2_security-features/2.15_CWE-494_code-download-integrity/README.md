# 무결성 검사 없는 코드 다운로드 (Download of Code Without Integrity Check) — CWE-494 / KISA 2.15

## 개념
원격 서버에서 실행 코드(플러그인·업데이트·스크립트·JAR 등)를 내려받아 무결성 검증 없이 실행하면,
전송 구간이 변조되거나 배포 서버가 침해될 경우 공격자가 임의 코드를 삽입해 실행시킬 수 있다.
"무결성 검사 없는 코드 다운로드"는 원격 코드 실행(RCE)으로 직결되는 위험한 약점이다.

## 취약 원인
- `new URL(url).openStream()` 으로 받은 바이트를 검증 없이 저장·실행한다.
- 다운로드한 파일의 체크섬(sha256)이나 배포자 서명을 확인하지 않는다.
- HTTP(평문) 또는 검증 없는 채널로 코드를 가져온다.

## 공격 시나리오
1. 애플리케이션이 시작 시 업데이트/플러그인을 원격에서 내려받는다.
2. 공격자가 중간자 위치에서 응답을 악성 코드로 바꾸거나 배포 서버를 침해한다.
3. 클라이언트가 무결성 검증 없이 받은 코드를 저장하고 실행한다.
4. 공격자의 코드가 클라이언트 권한으로 실행된다(RCE).

## 안전한 코딩
- 신뢰된 채널로 사전에 배포한 기대 체크섬(sha256)과 다운로드 결과를 비교한다.
- 더 강하게는 배포자 개인키 서명을 `Signature` 로 검증한다.
- 검증 실패 시 파일을 폐기하고 절대 실행하지 않는다.
- 코드 다운로드는 반드시 TLS로 수행한다.

## 취약 vs 안전 차이
| 구분 | 취약(Vulnerable) | 안전(Secure) |
|------|------------------|--------------|
| 무결성 검증 | 없음 | sha256 체크섬 비교 |
| 실패 처리 | 그대로 실행 | 폐기 후 예외 |
| 검증 도구 | 없음 | `MessageDigest`, (선택) `Signature` |

## CWE·KISA 매핑
- CWE-494: Download of Code Without Integrity Check
- KISA 소프트웨어 개발보안 가이드(2021) 보안기능 항목 2.15 무결성 검사 없는 코드 다운로드

## 실행/컴파일 방법
```bash
javac Vulnerable.java && java Vulnerable
javac Secure.java && java Secure
```
(실제 다운로드/실행 대신 구조를 보여준다. 운영에서는 네트워크·실행부에 주의한다.)
