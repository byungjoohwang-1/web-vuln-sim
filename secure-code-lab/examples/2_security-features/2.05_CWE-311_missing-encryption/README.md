# 암호화되지 않은 중요정보 (Missing Encryption of Sensitive Data) — CWE-311 / KISA 2.5

## 개념
비밀번호, 주민등록번호, 카드번호 같은 중요정보를 저장·전송할 때 암호화하지
않아, 파일 유출·로그 노출·네트워크 도청만으로 민감정보가 그대로 드러나는
약점이다.

## 취약 원인
- 민감정보를 평문 그대로 파일/DB/로그에 기록한다.
- 전송 구간을 평문(HTTP)으로 두어 중간에서 가로챌 수 있다.
- "내부망이라 괜찮다"는 잘못된 전제로 암호화를 생략한다.

## 공격 시나리오
1. 백업 파일이나 로그가 유출된다.
2. 공격자가 `members.txt`를 열어 비밀번호·주민번호·카드번호를 그대로 획득한다.
3. 획득한 정보로 계정 탈취, 명의 도용, 카드 부정 사용을 시도한다.

## 안전한 코딩
- 비밀번호는 복원 불필요하므로 저장하지 말고, 필요 시 솔트+해시(bcrypt 등)만 저장한다.
- 복호화가 필요한 값(카드·주민번호)은 AES/GCM 등으로 암호화해 저장한다.
- 전송 구간은 TLS(HTTPS)로 보호한다.
- 로그·에러 메시지에 민감정보 원문을 남기지 않는다.

## 취약 vs 안전 차이
| 구분 | 취약(Vulnerable) | 안전(Secure) |
|------|------------------|--------------|
| 저장 형태 | 평문 | AES/GCM 암호문 |
| 로그 노출 | 비밀번호 평문 출력 | 식별자만 출력 |
| 유출 시 피해 | 즉시 정보 노출 | 키 없이는 복호화 불가 |
