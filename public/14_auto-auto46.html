🤖 Android 인포테인먼트 디버그·IPC 남용

자동차 보안 · 고성능 컴퓨트(HPC)

위험도: 상
💡 쉽게 말하면
디버그 브리지 잔존은 매장 뒷문에 공사용 임시 열쇠를 그대로 꽂아 둔 것입니다. 앞문 보안은 훌륭한데 뒷문이 열려 있습니다.

🎯 직접 해보기 — 공격을 실행해 보세요

아래에서 시스템 상태를 취약 또는 안전(조치 적용)으로 바꾼 뒤 공격 실행을 눌러, 같은 공격이 어떻게 다르게 끝나는지 직접 확인하세요.

현재: 취약한 설정 — 공격이 통할까요?
# USB 포트에서 인포테인먼트 셸을 얻어 본다 # [공격 실행] 버튼을 누르면 시작합니다.

📋 설정 비교 (왜 막혔나?)

✗ 취약한 설정
# USB 포트에서 디버그 브리지 연결 attacker$ adb connect ; adb shell id >> uid=0(root) — 디버그 빌드 셸 획득 → IPC 드라이버 취약점으로 차량 HAL 접근
✓ 안전한 설정
# 릴리스 빌드 + 디버그 차단 + 최신 패치 ivi$ debuggable=0 ; adb disabled ; SELinux enforcing >> 디버그 브리지 연결 거부 → 권한 경계로 차량 HAL 접근 차단

🔧 조치 방법

  1. 양산은 릴리스 빌드로 배포하고 유선·무선 디버그 브리지를 비활성화합니다.
  2. 강제 접근제어를 활성 상태로 두고 차량 HAL 접근 권한을 최소화합니다.
  3. 안드로이드 보안 패치를 주기적으로 반영하고 커널 취약점 노출을 관리합니다.

✅ 점검 체크리스트

  • 디버그 브리지 비활성화 확인
  • 릴리스 빌드·강제 접근제어 적용
  • 보안 패치 주기 관리
