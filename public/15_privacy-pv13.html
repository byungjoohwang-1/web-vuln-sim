PV-13

🗑️ 파기 미흡 (복구 가능한 삭제)

개인정보보호 · 보유·파기

위험도: 상

📋 취약점 개요

개인정보를 파기할 때는 복구·재생되지 않는 방법을 써야 합니다. DB의 논리 삭제(flag), 휴지통 이동, 단순 파일 삭제는 파기가 아니며, 종이 출력물은 분쇄·소각해야 합니다.

🖥️ 상태 비교 시뮬레이션

privacy$ (취약)
# 회원 탈퇴 처리 app$ UPDATE users SET deleted=1 WHERE id=? >> 원본 레코드 그대로 존재 (플래그만 변경) >> 일 단위 백업본에도 개인정보 잔존 → 파기로 인정되지 않음 · 유출 시 그대로 노출

🔧 조치 방법

  1. 전자적 파일은 복원 불가능한 방법(영구 삭제·덮어쓰기)으로 파기하고, 기록물·출력물은 분쇄·소각합니다.
  2. 논리 삭제만 수행하는 코드 경로를 찾아 물리 파기 또는 비식별 처리로 교체합니다.
  3. 백업본·로그·캐시·개발 환경 복제본을 파기 범위에 포함해 점검합니다.
  4. 파기 일시·대상·방법·담당자를 개인정보파일 파기 관리대장에 기록합니다.
  5. 저장매체 폐기·반납 시 완전삭제 또는 물리적 파괴 절차를 적용합니다.

✅ 점검 체크리스트

  • 복구 불가능한 방법으로 파기됨
  • 백업·로그 등 사본까지 파기 범위에 포함됨
  • 파기 관리대장 기록 존재
