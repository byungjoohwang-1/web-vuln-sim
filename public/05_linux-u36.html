🔗 r 계열 서비스(rsh/rlogin/rexec) 비활성화

서비스 관리

위험도: 상
💡 쉽게 말하면
r 계열 서비스는 옆집이라고 말하면 그냥 들여보내는 경비와 같습니다. 신분 확인 없이 신뢰만으로 문을 열어 주고, 대화 내용도 평문이라 엿들리죠. 공격자는 신뢰 관계를 흉내 내 그대로 들어옵니다.

🎯 직접 해보기 — 공격을 실행해 보세요

아래에서 시스템 상태를 취약 또는 안전(조치 적용)으로 바꾼 뒤 공격 실행을 눌러, 같은 공격이 어떻게 다르게 끝나는지 직접 확인하세요.

현재: 취약한 설정 — 공격이 통할까요?
# 공격자가 신뢰관계를 악용해 비밀번호 없이 접속한다 # [공격 실행] 버튼을 누르면 시작합니다.

📋 설정 비교 (왜 막혔나?)

✗ 취약한 설정
# r 계열 서비스 확인 # grep -E "shell|login|exec" /etc/inetd.conf shell stream tcp nowait root /usr/sbin/in.rshd login stream tcp nowait root /usr/sbin/in.rlogind → 평문/신뢰기반 인증 사용 (취약)
✓ 안전한 설정
# r 계열 라인 주석 처리 # grep -E "shell|login|exec" /etc/inetd.conf #shell ... / #login ... / #exec ... → SSH로 대체, r 서비스 차단 (양호)

🔧 조치 방법

  1. inetd.conf의 shell/login/exec 라인을 주석 처리합니다.
  2. xinetd 사용 시 rsh/rlogin/rexec를 disable = yes 처리.
  3. 원격 접속은 SSH로 대체하고 .rhosts, /etc/hosts.equiv를 제거합니다.

✅ 점검 체크리스트

  • rsh/rlogin/rexec가 모두 비활성화되어 있는가
  • SSH로 원격 접속을 대체하였는가
  • .rhosts/hosts.equiv 신뢰 설정이 제거됨
