D-23

🎚️ 최소 권한 원칙(Role)

데이터베이스 보안

위험도: 상

📋 취약점 개요

사용자에게 권한을 직접·과다 부여하면 권한 관리가 어렵고 오남용 위험이 큽니다. 업무별 Role을 정의하고 최소 권한만 부여해야 합니다.

🖥️ 상태 비교 시뮬레이션

root@server:~# (취약)
-- 과다 권한 예시 SQL> SELECT * FROM dba_sys_privs WHERE grantee='APPUSER'; SELECT ANY TABLE / CREATE ANY PROCEDURE → ANY 권한 직접 부여 (취약)

🔧 조치 방법

  1. 업무 단위 Role을 정의하고 필요한 객체 권한만 부여합니다.
  2. SELECT ANY/CREATE ANY 등 ANY 권한을 회수합니다.
  3. 권한 부여 현황을 주기적으로 검토합니다.

✅ 점검 체크리스트

  • ANY 등 과다 권한이 회수됨
  • 업무 Role로 최소 권한이 부여됨
점검기준: 데이터베이스 > 최소 권한 원칙
