왜 뚫리고, 어떻게 막나
문자열 결합은 신뢰할 수 없는 입력을 SQL 본문에 섞습니다. 그래서 ' OR '1'='1' -- 가 쿼리의 논리를 바꿔버리고(-- 가 비밀번호 검사를 주석 처리), 인증이 우회됩니다. 파라미터 바인딩은 쿼리와 데이터를 분리된 채널로 보내 드라이버가 입력을 SQL로 해석하지 않으므로, 같은 페이로드가 그냥 문자열 리터럴이 되어 어떤 사용자와도 일치하지 않습니다.
VULNERABLE
// Java — 문자열 결합 (취약)
String q = "SELECT * FROM users WHERE "
  + "username='" + user + "' AND "
  + "password='" + pass + "'";
stmt.executeQuery(q);   // 입력이 SQL로 실행됨
SECURE
// Java — PreparedStatement (안전)
String q = "SELECT * FROM users WHERE "
  + "username=? AND password=?";
PreparedStatement ps = con.prepareStatement(q);
ps.setString(1, user); ps.setString(2, pass);
ps.executeQuery();      // 입력은 데이터로만 처리
⚠️ 교육용 시뮬레이션입니다. SQLite 엔진은 브라우저 안(sql.js / WebAssembly)에서만 로컬로 동작하며, 실제 서버·네트워크는 관여하지 않고 데이터가 기기를 벗어나지 않습니다.
