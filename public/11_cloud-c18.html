🔗 호스트 경로·네임스페이스 공유

클라우드/컨테이너 · 컨테이너

위험도: 상
💡 쉽게 말하면
hostPath와 hostPID 공유는 방(컨테이너)에 건물 복도로 통하는 비밀문을 내는 격입니다. 침입자가 그 문으로 호스트 파일과 프로세스에 닿습니다. 공유 제거는 비밀문을 벽으로 막습니다.

🎯 직접 해보기 — 공격을 실행해 보세요

아래에서 시스템 상태를 취약 또는 안전(조치 적용)으로 바꾼 뒤 공격 실행을 눌러, 같은 공격이 어떻게 다르게 끝나는지 직접 확인하세요.

현재: 취약한 설정 — 공격이 통할까요?
# 호스트 경로 공유를 통해 호스트 자원에 접근한다 # [공격 실행] 버튼을 누르면 시작합니다.

📋 설정 비교 (왜 막혔나?)

✗ 취약한 설정
# 호스트 공유 설정 $ kubectl get pod -o yaml | grep -E "hostPath|hostPID" hostPath: / , hostPID: true → 호스트 파일/프로세스 접근
✓ 안전한 설정
# 공유 제거 $ hostPath 제거, hostPID: false 호스트 격리 → 탈출 경로 차단

🔧 조치 방법

  1. 불필요한 hostPath, hostPID, hostNetwork 공유를 제거합니다.
  2. Pod Security Standards로 호스트 네임스페이스 사용을 금지합니다.

✅ 점검 체크리스트

  • 호스트 경로/네임스페이스 공유가 제한됨
점검기준: 컨테이너 보안 > 호스트 격리
