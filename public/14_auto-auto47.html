👑 과다권한 서비스·파일 권한 오류

자동차 보안 · 고성능 컴퓨트(HPC)

위험도: 중
💡 쉽게 말하면
과다 권한은 카페 아르바이트생에게 본사 마스터키를 쥐여 주는 것입니다. 실수 한 번의 결과가 매장 하나가 아니라 회사 전체가 됩니다.

🎯 직접 해보기 — 공격을 실행해 보세요

아래에서 시스템 상태를 취약 또는 안전(조치 적용)으로 바꾼 뒤 공격 실행을 눌러, 같은 공격이 어떻게 다르게 끝나는지 직접 확인하세요.

현재: 취약한 설정 — 공격이 통할까요?
# 최고 권한으로 도는 서비스와 느슨한 파일 권한을 찾아본다 # [공격 실행] 버튼을 누르면 시작합니다.

📋 설정 비교 (왜 막혔나?)

✗ 취약한 설정
# 서비스 실행 권한과 파일 권한 확인 attacker$ ps -o user,cmd ; find / -perm -4000 >> 미디어 서비스가 root 실행, 설정 디렉터리 0777 → 남은 setuid 도구로 즉시 권한 상승
✓ 안전한 설정
# 최소 권한 + 배포 전 권한 점검 hpc$ run as svc-media ; drop caps ; no setuid dev tools >> 서비스가 침해돼도 권한이 제한적 → 빌드 게이트에서 권한 이상 차단

🔧 조치 방법

  1. 서비스는 전용 계정과 최소 권한으로 실행하고 불필요한 권한을 제거합니다.
  2. 파일·디렉터리 권한을 검사하는 빌드·배포 게이트를 둡니다.
  3. 양산 이미지에서 setuid 개발 도구와 테스트 유틸리티를 제거합니다.

✅ 점검 체크리스트

  • 서비스 최소 권한 실행
  • 권한 검사 게이트 존재
  • 개발 유틸리티 제거
점검기준: 리눅스 권한 최소화 · 양산 이미지 점검

SDV·전동화 전환에서 달라지는 점

최소권한은 서버에서 오래된 원칙이지만, 차량 소프트웨어는 "어차피 닫힌 환경"이라는 가정 아래 느슨하게 만들어진 코드가 많습니다. 상시 연결과 앱 생태계가 그 가정을 깨뜨린 지금, 권한 설계를 다시 점검해야 하는 이유입니다.
