🕰️ 시간 및 상태 (TOCTOU)

상태 검사(Check)와 사용(Use) 시점의 불일치로 인한 보안 약점

🚫 취약한 모드

검사와 실행 사이에 딜레이가 있어 상태가 변조될 수 있음

✅ 안전한 모드

검사와 실행을 원자적(Atomic)으로 처리

📚 예전 책 분석: Java & Python 가이드

☕ Java: 경쟁 조건 (Race Condition) 
// [취약한 코드] 파일 존재 확인 후 삭제 사이에 파일이 변경/삭제될 수 있음
if (file.exists()) {
    // <-- 이 시점에 다른 프로세스가 파일에 접근하면 에러 발생
    file.delete();
}

// [안전한 코드] 원자적 연산 사용 또는 동기화 블록 사용
synchronized (lock) {
    if (file.exists()) {
        file.delete();
    }
}
// 또는 java.nio.file.Files의 원자적 메소드 사용
Files.deleteIfExists(path);
🐍 Python: TOCTOU (Time of Check to Time of Use) 
# [취약한 코드] os.path.exists 사용 후 open
import os
if os.path.exists(filename):
    f = open(filename, 'w') # <-- 그 사이에 심볼릭 링크로 교체될 위험 있음

# [안전한 코드] 예외 처리(Try-Except)를 통한 원자적 접근
try:
    fd = os.open(filename, os.O_CREAT | os.O_EXCL | os.O_WRONLY)
    f = os.fdopen(fd, 'w')
except OSError:
    print("File already exists")
