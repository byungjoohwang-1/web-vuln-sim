🔍 감사(Audit) 기능 활성화

데이터베이스 보안

위험도: 상
💡 쉽게 말하면
은행에 거래 기록이 전혀 안 남는다면, 내부 직원이 몰래 돈을 빼가도 추적할 수 없습니다. 감사(Audit) 기능이 꺼지면 권한 변경이나 중요 데이터 접근이 기록되지 않습니다. 그래서 감사를 켜두는 것이 사고 추적의 핵심입니다.

🎯 직접 해보기 — 공격을 실행해 보세요

아래에서 시스템 상태를 취약 또는 안전(조치 적용)으로 바꾼 뒤 공격 실행을 눌러, 같은 공격이 어떻게 다르게 끝나는지 직접 확인하세요.

현재: 취약한 설정 — 공격이 통할까요?
# 공격자가 감사가 꺼진 상태에서 흔적 없이 데이터를 빼낸다 # [공격 실행] 버튼을 누르면 시작합니다.

📋 설정 비교 (왜 막혔나?)

✗ 취약한 설정
-- 감사 설정 확인 SQL> SHOW PARAMETER audit_trail audit_trail string NONE → 보안 이벤트 미기록 (취약)
✓ 안전한 설정
-- 감사 활성화 SQL> ALTER SYSTEM SET audit_trail=DB,EXTENDED SCOPE=SPFILE; AUDIT CREATE SESSION; AUDIT ALTER USER; → 감사 기능 활성화 (양호)

🔧 조치 방법

  1. AUDIT_TRAIL을 DB(또는 OS)로 설정 후 재기동합니다.
  2. 접속, 권한 변경, 중요 객체 접근 등에 대해 AUDIT을 설정합니다.
  3. 최신 버전은 Unified Auditing 정책을 사용합니다.

✅ 점검 체크리스트

  • AUDIT_TRAIL이 활성화됨
  • 중요 이벤트에 감사 정책이 설정됨
